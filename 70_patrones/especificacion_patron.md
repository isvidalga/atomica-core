# Propósito

Este documento define la estructura obligatoria de todos los patrones organizacionales de ATÓMICA.

Su objetivo es garantizar que todo el catálogo utilice el mismo lenguaje, el mismo nivel de abstracción y las mismas reglas metodológicas.

Ningún patrón puede añadir, eliminar o modificar apartados definidos en esta especificación.

Toda evolución de la estructura deberá realizarse modificando este documento.

---

# Naturaleza

Un patrón organizacional representa una hipótesis estructural sobre el funcionamiento de una organización.

No representa un evento.

No representa una incidencia.

No representa una capacidad.

No representa una fragilidad.

Describe una configuración recurrente observada mediante múltiples evidencias.

---

# Estructura obligatoria

Todos los documentos del catálogo deberán respetar el siguiente orden.

---

# Identificación

Debe incluir:

- identificador único;
- nombre oficial;
- versión;
- estado.

---

# Propósito

Describe qué comportamiento organizacional pretende identificar el patrón.

Debe escribirse en una única idea.

---

# Definición

Define el patrón desde un punto de vista metodológico.

Debe ser independiente de cualquier empresa concreta.

---

# Qué detecta

Describe los comportamientos compatibles con el patrón.

---

# Qué no detecta

Define explícitamente los casos que no pertenecen al patrón.

Este apartado evita falsas detecciones.

---

# Señales compatibles

Lista de señales organizacionales que pueden contribuir a la detección.

Las señales no constituyen evidencia suficiente por sí mismas.

---

# Evidencias compatibles

Describe las evidencias que pueden aumentar la confianza del patrón.

No implica que todas sean obligatorias.

---

# Hipótesis relacionadas

Hipótesis organizacionales que pueden fortalecerse mediante este patrón.

---

# Capacidades relacionadas

Capacidades organizacionales potencialmente implicadas.

La relación nunca implica causalidad.

---

# Fragilidades relacionadas

Fragilidades compatibles con el patrón.

Un patrón puede relacionarse con varias fragilidades.

---

# Condiciones de detección

Define los criterios mínimos para considerar el patrón detectado.

No describe la implementación técnica.

Describe únicamente las condiciones metodológicas.

---

# Condiciones de falsación

Describe qué observaciones o evidencias debilitan o descartan el patrón.

Todo patrón debe poder refutarse.

---

# Nivel mínimo de confianza

Indica el nivel de confianza recomendado antes de presentar el patrón como interpretación relevante.

---

# Riesgo organizacional

Describe las posibles consecuencias de mantener el patrón en el tiempo.

---

# Intervenciones compatibles

Relaciona tipos generales de intervención.

No prescribe acciones concretas.

---

# Observaciones

Información metodológica adicional cuando resulte necesaria.

Este apartado es opcional.

---

# Restricciones

Todos los patrones deberán cumplir las siguientes reglas:

- representar estructuras, nunca eventos;
- ser falsables;
- ser trazables;
- admitir distintos niveles de confianza;
- mantenerse independientes de cualquier implementación tecnológica;
- utilizar únicamente conceptos definidos en la ontología oficial;
- evitar recomendaciones prescriptivas.

---

# Convenciones

Todos los patrones utilizan:

- la misma estructura;
- la misma terminología;
- el mismo orden de apartados;
- el mismo nivel de abstracción.

No se permiten documentos especiales para casos particulares.
