# Pattern

Estado: CANÓNICO

Versión: 1.0

Ubicación:

```
50_producto/pattern.md
```

---

# Propósito

Pattern constituye el instrumento de exploración estructural del Modelo Vivo.

No genera conocimiento.

No realiza inferencias.

No interpreta acontecimientos aislados.

Su función consiste en permitir comprender las estructuras recurrentes representadas por el Modelo Vivo.

Pattern responde a una única pregunta:

> ¿Por qué este comportamiento tiende a repetirse?

---

# Naturaleza

Pattern pertenece al Producto.

No pertenece al Canon.

No pertenece a la Ontología.

No constituye un sistema de diagnóstico.

No representa una cronología.

No identifica causas únicas.

Representa patrones estructurales inferidos a partir del conocimiento disponible.

---

# Principios

## PAT-001 · Los patrones representan estructuras

Pattern representa estructuras persistentes.

Nunca representa acontecimientos individuales.

---

## PAT-002 · Toda exploración conserva el contexto

Toda exploración comienza desde un elemento previamente observado.

Pattern nunca constituye un punto de entrada independiente.

---

## PAT-003 · Los patrones evolucionan

Todo patrón puede fortalecerse, debilitarse, transformarse o dejar de estar activo.

Su evolución depende exclusivamente de la incorporación de nuevo conocimiento.

---

## PAT-004 · Toda representación es trazable

Todo patrón debe poder recorrerse hasta:

- las relaciones que lo sustentan;
- las hipótesis asociadas;
- las evidencias disponibles;
- las observaciones originales.

---

# Punto de exploración

Pattern siempre se explora desde un contexto previo del Modelo Vivo.

Habitualmente desde:

- Observe;
- una tensión;
- una relación;
- un Sistema Organizacional;
- una hipótesis.

Pattern nunca constituye un punto de entrada independiente.

---

# Unidad de análisis

Pattern trabaja exclusivamente sobre patrones organizacionales.

Nunca representa:

- personas;
- departamentos;
- acontecimientos aislados;
- responsables individuales.

---

# Información representada

Cada patrón puede mostrar, entre otros:

- identificación;
- descripción;
- Sistemas Organizacionales implicados;
- relaciones relevantes;
- nivel de confianza;
- evidencia asociada.

Nunca representa:

- recomendaciones;
- planes de acción;
- responsables;
- decisiones.

---

# Relaciones

Un patrón puede involucrar uno o varios Sistemas Organizacionales.

Pattern representa relaciones estructurales.

Nunca jerarquías organizativas.

---

# Evolución

Todo patrón puede:

- fortalecerse;
- debilitarse;
- transformarse;
- dejar de estar activo.

La evolución depende exclusivamente de la incorporación de nuevo conocimiento.

---

# Relación con el Modelo Vivo

Pattern representa patrones contenidos en el Modelo Vivo.

Nunca genera patrones propios.

Toda representación depende del estado vigente del Modelo.

---

# Restricciones

## PAT-001

Nunca afirmar causalidad.

---

## PAT-002

Nunca identificar culpables.

---

## PAT-003

Nunca predecir resultados.

---

## PAT-004

Nunca generar conocimiento nuevo.

---

## PAT-005

Nunca representar información ajena al Modelo Vivo.

---

# Criterios de aceptación

La implementación de Pattern se considera correcta únicamente si cumple todas las condiciones siguientes:

- Todo patrón conserva su trazabilidad.
- Toda representación depende del Modelo Vivo.
- Ningún patrón se presenta como un hecho.
- Nunca se representan causalidades demostradas.
- Pattern nunca genera conocimiento propio.

---

# Filosofía

Las organizaciones no evolucionan mediante acontecimientos aislados.

Evolucionan mediante estructuras que tienden a repetirse.

Pattern no pretende explicar toda la organización.

Hace visibles las estructuras recurrentes que el Modelo Vivo considera suficientemente fundamentadas para orientar la comprensión del sistema.
